## Abstract

Yago v0.0.69 stops the crawler from retrying, without end, a terminal crawl settlement that the node no longer holds. The node now answers such a settlement with `NotFound` instead of `FailedPrecondition`; lease loss to another session keeps `FailedPrecondition`. On `NotFound` the crawler removes that exact settlement from its durable outbox and logs one warning. Lease loss and transient failures are still retried. The change alters one node-crawler status code; no message shape, setting, environment variable, listener or dependency changes. Upgrade the node and crawler together; an older crawler against this node keeps the previous retry behavior.

## Changes

### Stop retrying terminal settlements the node no longer holds

A crawler reports a finished or cancelled crawl order through a two-phase terminal settlement kept in a durable outbox. The node keeps its own settlement record for 24 hours. When the lease and its record were gone, or the recorded settlement differed, the node answered with `FailedPrecondition`, the same code it uses when another session owns the lease. The crawler could not tell the two cases apart, kept the outbox row, and retried it about once a second without end. In observed operation a small number of such rows produced tens of thousands of warnings per day while crawling otherwise continued.

The node now answers a rich terminal acknowledgement or confirmation it no longer holds, or holds with a different definition, with `NotFound`. Lease loss keeps `FailedPrecondition`, because it can be resolved when the crawler's current session adopts the lease. Other failures remain `Internal`.

On `NotFound` the crawler settlement relay removes the outbox row whose lease and order identity match exactly, logs the warning `terminal crawl settlement refused by node; discarded` once with the lease identifier, and stops. A removal whose order identity differs from the stored row is refused. On `FailedPrecondition` or a transient failure the row is kept and retried as before. If the removal itself fails, both errors are reported and the row is retried on the next pass.

## Compatibility

- No YaCy, Tavily or node-crawler message shape changes. The gRPC status code for a refused rich terminal settlement changes from `FailedPrecondition` to `NotFound`; status codes are not part of the protobuf schema.
- An older crawler against this node treats `NotFound` as a non-retryable call failure and retries the outbox row on its next reconciliation pass, which matches its previous behavior.
- This crawler against an older node continues to receive `FailedPrecondition` and keeps retrying such rows.
- No setting, environment variable, listener, service, image repository or new dependency is added.
- The reusable-module API gate compares against the exact previous published v0.0.68 tag and source commit.

## Upgrade and rollback

Verify the published package's GitHub-hosted attestation against repository `D4rk4/yago`, the exact release workflow, tag ref and source commit. Use matching node and crawler binaries. Preserve configuration and data; ordinary deployments should use the established stopped-service backup procedure. Where an explicit target-specific operator policy omits a new pre-upgrade backup, preserve every existing archive unchanged.

Stop the crawler and node, install the published package, then start and verify the node before starting the crawler. The package enables the units but does not start them automatically. After the first start, each terminal settlement that the node no longer holds is logged once as discarded and is not retried.

Rollback reinstalls the previous verified matching package with both services stopped. Settlements already discarded are not restored; settlements still in the outbox are retried by the older version as before.

## Known limitations

- Removing a refused settlement leaves the completed run's local frontier checkpoint in place, because the node may lease the same order again.
- A lease held under a different live session still answers `FailedPrecondition` and is retried until the node reclaims it.
- Bug #3 (node memory use) remains open; this release does not change memory behavior.
